# Задача для Codex: MVP сервиса НЭН «Что почитать и посмотреть с ребёнком»

## Контекст

Работай в локальном репозитории:

`/Users/veronika/Documents/GitHub/nen_dashboard`

Нужно реализовать работающий MVP отдельного веб-сервиса семейного медиа НЭН:

**«Что почитать и посмотреть с ребёнком»**

Сервис помогает родителям быстро выбрать книгу, классическую сказку, мультфильм или семейный фильм по возрасту ребёнка, интересам, настроению, доступному времени и ситуации использования.

Это не интернет-магазин, не каталог издательства и не административный дашборд. Это самостоятельный рекомендательный сервис внутри экосистемы НЭН.

Первая версия работает на локальной базе из 50 произведений, без регистрации, серверной базы, CMS и внешнего AI API.

# 3. Данные

Вместе с этим заданием предоставлен файл:

`catalog.json`

Помести его в подходящую директорию проекта, например:

`src/data/catalog.json`

или в уже принятую в проекте директорию данных.

Не редактируй содержимое исходного JSON вручную без необходимости. Создай типизированный слой адаптации.

Пример TypeScript-типа:

```ts
export type ContentType = "fairy-tale" | "book" | "cartoon" | "movie";

export interface CatalogItem {
  id: string;
  slug: string;
  title: string;
  originalTitle: string | null;
  contentType: ContentType;
  categoryLabel: string;
  creator: string | null;
  contributor: string | null;
  studioOrPublisher: string | null;
  countryOrTradition: string | null;
  originalYear: number | string | null;
  referenceEditionOrRelease: string | null;
  isbnOrIdentifier: string | null;
  pageCount: number | null;
  durationMinutes: number | null;
  officialAgeRatingRu: string | null;
  officialAgeRatingSource: string | null;
  recommendedAgeMin: number;
  recommendedAgeMax: number;
  ageGroups: string[];
  genres: string[];
  interests: string[];
  moods: string[];
  suitableForBedtime: boolean;
  suitableForFamily: boolean;
  suitableForIndependentUse: boolean;
  durationCategory: string | null;
  imageUrl: string | null;
  shortDescription: string | null;
  editorialNote: string | null;
  metadataSource: string | null;
  verificationStatus: string | null;
  annotationStatus: string | null;
  note: string | null;
}
```

В текущей базе нет подготовленных обложек и полных редакционных описаний.

Поэтому:

- не загружай случайные изображения из интернета;
- не выдумывай факты о сюжете;
- создай качественный детерминированный placeholder для каждой карточки: типографическая обложка с названием, типом контента и вариативной композицией;
- одинаковое произведение всегда должно получать одинаковый placeholder;
- если позже появится `imageUrl`, компонент должен автоматически использовать реальную обложку;
- если `shortDescription` отсутствует, выводи короткую нейтральную строку, собранную из имеющихся жанров, интересов и настроения, например: «Приключенческая история о дружбе и семье»;
- не показывай пользователю служебные поля проверки и источники метаданных в основной карточке.

# 4. Границы MVP

В первую версию входят:

1. Главная страница.
2. Быстрый подбор по параметрам.
3. Каталог с фильтрами.
4. Результаты, отсортированные по релевантности.
5. Подробная страница произведения.
6. Локальное избранное.
7. Поиск по названию, оригинальному названию, автору или режиссёру, студии/издательству, жанрам и интересам.
8. Адаптивная мобильная и десктопная версии.

Не входят:

- регистрация;
- личный кабинет;
- серверная база;
- CMS;
- платежи;
- отзывы пользователей;
- внешние рекомендации AI;
- автоматический импорт контента;
- ссылки на покупку как центральная функция.

# 5. Основной пользовательский путь

Пользователь должен получить результат без регистрации:

**зайти → выбрать возраст → при желании выбрать формат и дополнительные параметры → нажать «Подобрать» → увидеть результаты → открыть произведение**

Весь путь до первой выдачи должен занимать меньше минуты.

Возраст — единственный обязательный параметр в быстром подборе. Остальные параметры можно пропустить.

---

# 6. Главная страница

Главная должна восприниматься как вход в самостоятельный сервис, а не как статья или рекламный лендинг.

Обязательные элементы:

- компактная шапка с логотипом НЭН;
- рабочее название сервиса;
- короткое объяснение:
  «Выберите возраст и интересы ребёнка — покажем книги, сказки, мультфильмы и фильмы, которые могут подойти»;
- заметный выбор возраста;
- выбор типа контента:
  - всё;
  - книги и сказки;
  - мультфильмы;
  - фильмы;
- основная кнопка «Подобрать»;
- ссылка «Посмотреть весь каталог»;
- блок быстрых подборок;
- несколько примеров произведений.

Быстрые подборки строятся из фильтров, а не дублируются отдельными массивами:

- «Спокойное перед сном»;
- «Смешное про животных»;
- «Для семейного вечера»;
- «Приключения для 8–10 лет».

Не заставляй пользователя проходить длинный пошаговый опрос. Основной вариант — компактная форма или панель. После выбора возраста можно раскрыть дополнительные параметры.

# 7. Подбор и фильтры

Параметры:

## Возраст

Используй точный возраст ребёнка от 2 до 14 лет или понятные возрастные кнопки. Выбранное число проверяется по `recommendedAgeMin` и `recommendedAgeMax`.

## Тип контента

- всё;
- книги и сказки;
- мультфильмы;
- фильмы.

Классические сказки и современные книги можно объединить в пользовательском фильтре «Книги и сказки», но визуально различать в карточках.

## Интересы

Используй только значения, реально встречающиеся в JSON. Не показывай пустые фильтры.

## Настроение

Используй только значения, реально встречающиеся в JSON.

## Ситуация

- перед сном;
- всей семьёй;
- самостоятельно.

## Длительность

Для экранного контента:

- до 15 минут;
- до 30 минут;
- до 60 минут;
- до 90 минут;
- больше 90 минут.

Для книг:

- короткая история;
- на один вечер;
- на несколько вечеров;
- длинная книга.

Не показывай фильтр, если в текущей выборке для него нет ни одного результата.

# 8. Логика рекомендаций

Вынеси логику в отдельный чистый модуль, например:

`src/lib/recommendations.ts`

Не размещай расчёты внутри JSX.

## Жёсткие ограничения

Всегда строго учитываются:

- рекомендуемый возраст НЭН;
- тип контента, если выбран;
- категория длительности, если выбрана;
- «перед сном», «всей семьёй» или «самостоятельно», если включены.

## Интересы

Если выбран один интерес, произведение в основной выдаче должно содержать этот интерес.

Если выбрано несколько интересов:

1. сначала показывай произведения, совпавшие со всеми выбранными интересами;
2. затем — совпавшие с частью интересов, но визуально отделяй их блоком «Ещё может подойти».

Не подмешивай произведения, не совпавшие ни с одним интересом, в основную выдачу.

## Настроение

Для основной выдачи требуется совпадение хотя бы с одним выбранным настроением. Большее число совпадений повышает результат.

## Ранжирование

После прохождения жёстких условий начисляй понятные внутренние веса:

- совпадение каждого интереса — высокий вес;
- совпадение настроения — средний вес;
- совпадение нескольких параметров — бонус;
- более точное попадание в середину возрастного диапазона — небольшой бонус;
- произведения разных типов и жанров не должны полностью вытеснять друг друга, если пользователь выбрал «всё».

Веса вынеси в конфигурацию.

## Объяснение

Не показывай технический score.

Для каждой карточки сформируй 1–3 причины:

- «Подходит для 6–8 лет»;
- «Про животных и дружбу»;
- «Можно посмотреть всей семьёй»;
- «Укладывается в 30 минут»;
- «Спокойное и уютное».

Если точных результатов нет:

- не показывай пустой экран сразу;
- объясни, какой параметр слишком сузил выбор;
- предложи снять конкретный фильтр;
- отдельно покажи ближайшие варианты под заголовком «Можно попробовать ещё»;
- явно сообщи, что они соответствуют запросу не полностью.

# 9. Каталог и результаты

Экран результатов содержит:

- заголовок, собранный из запроса;
- количество точных совпадений;
- активные фильтры в виде удаляемых тегов;
- кнопку «Изменить подбор»;
- кнопку «Сбросить»;
- строку поиска;
- сортировку:
  - сначала подходящие;
  - по возрасту;
  - сначала короткие;
  - по названию;
- сетку карточек;
- отдельный блок частичных совпадений, если он нужен.

Состояние фильтров синхронизируй с URL query parameters, чтобы подборку можно было открыть по ссылке и восстановить после перезагрузки.

На мобильном фильтры открываются в drawer/bottom sheet или другом паттерне, уже используемом в проекте.

В каталоге показывай:

- placeholder или обложку;

- тип;
- рекомендуемый возраст НЭН;

Показывай:

# 12. Избранное

Регистрация не требуется.

Используй `localStorage`.

Требования:

- сохранение по `id`;
- восстановление после перезагрузки;
- кнопка на карточке и подробной странице;
- счётчик в навигации;
- отдельный экран или вкладка;
- понятное пустое состояние;
- приложение не падает при повреждённых данных `localStorage`;
- доступ к `localStorage` безопасен для SSR, если проект использует SSR.

---

# 13. Поиск

Поиск должен работать без перезагрузки и учитывать:

- `title`;
- `originalTitle`;
- `creator`;
- `studioOrPublisher`;
- `genres`;
- `interests`.

Нормализуй регистр, пробелы и `ё/е`.

Для первой версии достаточно подстрочного поиска. Архитектура должна позволять позднее заменить его на серверный полнотекстовый поиск.

# 18. Критерии готовности

MVP считается готовым, если:

- пользователь без регистрации выбирает возраст и получает результаты;
- фильтры реально работают на `catalog.json`;
- выбранный интерес не приводит к нерелевантным результатам в основной выдаче;
- есть отдельное отображение частичных совпадений;
- URL восстанавливает фильтры;
- поиск работает;
- карточки открывают подробную страницу;
- избранное сохраняется после перезагрузки;
- интерфейс адаптивен;
- визуально сервис связан с НЭН, но не выглядит копией ленты статей;
- production build проходит успешно.

# 19. Порядок работы
