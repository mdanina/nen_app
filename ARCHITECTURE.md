# Архитектура проекта НЭН

Проект организован как небольшой pnpm workspace-монорепозиторий. Сейчас реализован только самостоятельный книжный сервис «Что почитать с детьми». Сервис фильмов и мультфильмов не входит в его интерфейс и сборку.

## Структура репозитория

```text
nen_app/
  apps/
    books/                 # самостоятельное React/Vite-приложение книг
      src/
        app/               # точка сборки приложения и маршрутизация
        components/        # книжные карточки, фильтры и навигация
        data/              # BooksRepository и книжные подборки
        domain/books/      # модель, поиск, фильтрация и рекомендации
        hooks/             # избранное и SEO
        pages/             # страницы книжного сервиса

  packages/
    ui/                    # общие UI-примитивы и состояния
    search/                # нормализация и текстовый поиск
    data-core/             # базовые типы репозитория и валидации
    config/                # общие дизайн-токены

  data/
    source/                   # выгрузки издательств, OpenLibrary, редакторские правки
    generated/books.json      # собранный каталог, источник истины (2500 книг)
    generated/cover-cache.json # какие обложки уже лежат в собственном кеше

  scripts/
    build-books-catalog.mjs   # сборка каталога, публичные слаги, файлы для браузера
    build-books-permalinks.mjs # 2500 постоянных страниц, sitemap.xml, robots.txt
    books/cache-covers.mjs    # обложки в собственный кеш

  docs/                    # инструкции для редактора и дополнительные решения
  pnpm-workspace.yaml
  vercel.json
```

## Общие пакеты

- `@nen/ui` — иконки, состояния загрузки и отсутствия данных. В будущем здесь могут находиться базовые контейнеры карточек, chips и мобильные панели.
- `@nen/search` — нормализация русского текста, поддержка `е/ё`, токенизация и базовое текстовое сопоставление.
- `@nen/data-core` — общие контракты репозиториев, ошибки валидации и утилиты справочников.
- `@nen/config` — цвета, размеры, радиусы, тени и остальные дизайн-токены НЭН.

Книжная модель, расчёт похожих книг и правила книжных рекомендаций остаются внутри `apps/books`. Они не выносятся в общий код, поскольку относятся только к книгам.

## Будущий сервис «Что посмотреть с детьми»

Когда начнётся разработка экранного сервиса, он будет добавлен как отдельное приложение:

```text
apps/
  books/
  watch/
```

`apps/watch` получит собственные:

- `package.json`, Vite-конфигурацию и точку входа;
- маршруты и навигацию;
- модели фильмов и мультфильмов;
- базу или репозиторий экранного контента;
- фильтры длительности, формата, студии и возраста;
- отдельную production-сборку и Vercel-проект.

Он сможет использовать `packages/ui`, `packages/search`, `packages/data-core` и `packages/config`, но не будет импортировать книжные компоненты и книжную бизнес-логику. Поэтому оба сервиса смогут развертываться на разных доменах и выпускаться независимо.

## Как добавить новую книгу

1. Добавить запись в `data/source/catalog-full.json` с типом `book` или `fairy-tale`.
2. Обязательно заполнить:
   - `id`;
   - уникальный человекочитаемый `slug`;
   - `title`;
   - `contentType`;
   - `recommendedAgeMin`;
   - `recommendedAgeMax`.
3. Неизвестные факты оставить пустыми. Официальный рейтинг указывать только вместе с надёжным источником.
4. Выполнить:

```bash
pnpm catalog:build
```

5. Скрипт проверит обязательные поля, возраст, повторяющиеся `id` и `slug`, после чего обновит `data/generated/books.json`.
6. Выполнить `pnpm test` и `pnpm build`.

React-компоненты при добавлении книги изменять не требуется. Фильтры и справочники строятся из данных автоматически.

Дополнительная редакторская инструкция находится в [docs/catalog-editor-guide.md](./docs/catalog-editor-guide.md).

## Локальный запуск

Из корня репозитория:

```bash
pnpm install
pnpm dev
```

`pnpm dev` запускает только workspace-приложение `@nen/books` на `http://localhost:5173`.

Другие полезные команды:

```bash
pnpm catalog:build  # пересобрать книжный каталог
pnpm typecheck      # проверить TypeScript во всех workspace-пакетах
pnpm lint           # выполнить текущую статическую проверку
pnpm test           # запустить unit-тесты
pnpm build          # сформировать каталог и production-сборку книг
```

Готовая сборка появляется в `apps/books/dist`.

## Адреса и деплой

Сервис живёт в подкаталоге основного сайта: `n-e-n.ru/knigi/`. Общий домен нужен,
чтобы SEO-вес шёл на `n-e-n.ru`, а перелинковка со статьями не считалась внешней.

| Страница | Адрес |
|---|---|
| Главная | `/knigi/` |
| Каталог | `/knigi/katalog` |
| Книга | `/knigi/kniga/<слаг>` |
| Подборки | `/knigi/podborki`, `/knigi/podborki/<слаг>` |
| Подбор книги | `/knigi/podbor` |
| Избранное | `/knigi/izbrannoe` (закрыто от индексации) |

Базовый путь и домен задаются переменными `BOOKS_BASE_PATH` и
`BOOKS_PUBLIC_ORIGIN`; значения по умолчанию — боевые. Старые английские адреса
(`/books/<слаг>`, `/catalog`, `/collections`) приложение понимает и переводит на
действующие — это подстраховка для ссылок из превью.

Порядок выката, блок nginx и проверки после — [docs/deploy-nen.md](./docs/deploy-nen.md).

### Слаг книги

Публичный слаг собирается из названия на этапе сборки каталога
(`scripts/books/public-slug.mjs`), а не берётся из выгрузки. Иначе в адрес
попадает имя поставщика данных и технический идентификатор:
`samokat-istoriya-ernesta-i-selestiny-istoriya-ernesta-i-selestiny`,
`100-skazok-ol19978384w`. Совпадения разрешаются фамилией автора, затем номером;
результат не зависит от порядка записей в источнике.

### Что грузит браузер

Каталог не входит в JS-бандл. Сборка кладёт в `apps/books/public/data`:

- `catalog-index.json` — поля для списка, фильтров и поиска, включая выдержку
  описания (3,5 МБ, 527 КБ в gzip);
- `books/<слаг>.json` — полная запись книги, около 5 КБ.

Страница книги догружает свой файл; полное описание и выходные данные в индексе
не лежат. Раньше все 2500 записей компилировались в бандл — 13,2 МБ JS.

## Обновление каталога без изменения компонентов

Интерфейс работает через `BooksRepository`, а не импортирует записи непосредственно в страницы и карточки. Сейчас используется `StaticBooksRepository`, который читает проверенный JSON-снимок.

Поток данных выглядит так:

```text
редакторский источник
  → проверка и нормализация
  → data/generated/books.json
  → BooksRepository
  → поиск, фильтры и страницы
```

В дальнейшем источник можно заменить на Google Sheets, headless CMS, Supabase или собственный API. Для этого потребуется новая реализация `BooksRepository`; компоненты каталога, карточек и страниц менять не придётся.

Для текущего JSON-варианта обновление выполняется командами:

```bash
pnpm catalog:build
pnpm test
pnpm build
```
