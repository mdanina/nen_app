# Массовый импорт Open Library

Импорт работает отдельно от production-каталога и не подключён к книжному приложению. Его пользовательская сущность — одна книга. Произведения с одинаковыми нормализованными названием и набором авторов объединяются, а все связанные издания, ISBN и источники остаются во внутреннем слое.

## Поток данных

1. Официальные Open Library dumps или их локальные фрагменты (`.txt` или `.txt.gz`).
2. Неизменённая строка источника в SQLite (`source_records`).
3. Нормализованные авторы, произведения и издания.
4. Явный первичный отбор детских записей по `subjects`.
5. Объединение произведений и изданий в одну staging-книгу.
6. JSONL-выгрузка для проверки редакцией. Автоматического перехода в production нет.

## Инкрементальность

Для записи сохраняются тип сущности, Open Library ID, revision и хеш исходного JSON. Повторный dump пропускает неизменённые записи. Более новая revision обновляет только затронутую сущность и пересобирает связанные staging-книги. Сомнительное совпадение не объединяется: точное автоматическое объединение требует одинаковых нормализованных названия и идентификаторов авторов.

## Запуск

```powershell
pnpm import:openlibrary:large -- `
  --input D:\openlibrary\ol_dump_authors_latest.txt.gz `
  --input D:\openlibrary\ol_dump_works_latest.txt.gz `
  --input D:\openlibrary\ol_dump_editions_latest.txt.gz `
  --database data/import/openlibrary/state/catalog.sqlite `
  --output data/import/openlibrary/exports/2026-07 `
  --dump-date 2026-07-31 `
  --retrieved-at 2026-07-31T12:00:00.000Z `
  --batch-id openlibrary-2026-07
```

Для локальной проверки на небольшом фрагменте:

```powershell
pnpm import:openlibrary:large:fixture
```

## Выходные данные

- `books.jsonl` — простая staging-модель книги и ссылки на внутренние записи;
- `editions.jsonl` — издания, ISBN, издатели, языки и страницы;
- `annotations.jsonl` — полный исходный текст, происхождение и статус прав;
- `covers.jsonl` — только внешние URL и идентификаторы, без скачивания;
- `provenance.jsonl` — происхождение полей книги;
- `aliases.jsonl` — смена внутреннего канонического идентификатора;
- `report.json` — статистика запуска.

Поля возраста, редакционных тем и настроения не выводятся из `subjects` и не генерируются. Если источник не содержит их явно, в staging-книге остаются `null` и пустые массивы. Свободные рубрики источника сохраняются отдельно как `internal.sourceSubjects`. Аннотации не сокращаются и имеют `public_use: "unknown"`, пока допустимость публикации не подтверждена отдельно.
